## 2. 数据上报报文

### 2.1 直连设备遥测

Topic：`topic.telemetry`，缺省为 `v1/devices/me/telemetry`。设备身份由 MQTT 连接凭据确定。以下为结构占位，填写型号文档时以第 3 节全部已确认测点替换示例键。

```json
{
  "ts": 1792459200000,
  "values": {
    "【数值测点协议键】": 230.5,
    "【状态测点协议键】": 0
  }
}
```

公共指南第 7 章还允许直接发送键值对象（无 `ts`，平台接收时间作为数据时间），以及由多个 `ts/values` 对象组成的数组（批量上报、历史补传）。补传必须保留原始采集时间。

### 2.2 网关代理子设备遥测

Topic：`topic.gw_telemetry`，缺省为 `v1/gateway/telemetry`。网关使用自身凭据连接，以报文顶层的子设备名称区分设备；该名称必须与 `v1/gateway/connect` 的 `device` 一致，不能默认等同于 Modbus 站号。

```json
{
  "【子设备名称】": [
    {
      "ts": 1792459200000,
      "values": {
        "【数值测点协议键】": 230.5,
        "【状态测点协议键】": 0
      }
    }
  ]
}
```

网关订阅成功后先发布子设备上线消息，再上报数据；离线消息和网关断开行为按公共指南第 9、11 章处理。一条报文可以包含多个子设备。

### 2.3 报文结构与数据约定

| 字段 | JSON 类型 | 含义 | 说明 |
| --- | --- | --- | --- |
| ts | integer | 采集时间 | UTC Unix 毫秒时间戳；历史补传使用原始采集时间 |
| values | object | 测点键值 | 字段定义见第 3 节 |
| 【子设备名称】 | array | 网关代理的子设备记录 | 仅网关报文使用；数组元素承载本子设备的采集数据 |

新模板不采用旧文档的 `header.time/client/slaveid` 和 `data` 外壳。直连身份由凭据确定；网关子设备身份由顶层子设备名称确定。旧报文如需兼容，必须另列适用版本及转换规则，不能混入新格式。

数值是否已经转换为工程量必须在第 3 节逐项确认，不能仅凭 Modbus 系数推断 MQTT 已完成换算。QoS 1 可能重复投递，平台按“设备 + ts + 键”去重；未知字段按公共指南忽略。

## 3. 测点定义

【只读字段的保留范围以《新版协议命名规则(更新到ESM3).xlsx》对应型号为准，表中没有的字段删除，不从 Modbus 文档或平台扩展字段补回。此次范围核对只处理字段是否保留及数量，不调整已有名称映射、单位和编码。协议键沿用已经确认的 MQTT 键。】

| 序号 | 中文名称 | 协议键 | JSON 类型 | 单位 | 取值说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 【测点名称】 | 【协议键】 | number | 【单位】 | 【数值含义、已确认的有效范围或精度】 |

表中 `integer` 表示不带小数的 JSON 数字，`number` 表示可带小数的 JSON 数字；字符串、布尔值分别标记为 `string`、`boolean`。单位“—”表示无单位。底层寄存器的 `int16`、`float32` 不作为 JSON 数据类型填写。

## 6. 可读写配置参数

### 6.1 参数定义与 Modbus 对照

按各型号 Modbus 文档逐项填写可读写配置参数，MQTT 配置键列保留为空。

| 参数及原文约束 | MQTT 配置键 | Modbus 寄存器 | 字长 / 类型 / 权限 | Modbus 系数及单位 | 原文复位值 | 生效条件 | 删除行为 |
| --- | --- | --- | --- | --- | --- | --- | --- |

### 6.2 配置属性推送与删除

直连设备订阅 `topic.attributes_sub`（缺省 `v1/devices/me/attributes`）。平台仅推送发生变化的已支持配置键：

```json
{ "【已确认配置键】": 30 }
```

删除配置时，公共指南规定设备恢复该项本地缺省值：

```json
{ "deleted": ["【已确认配置键】"] }
```

网关订阅 `v1/gateway/attributes`，平台发送结构如下；`data` 也可替换为上述 `deleted` 对象：

```json
{ "device": "【子设备名称】", "data": { "【已确认配置键】": 30 } }
```

公共指南未定义配置执行结果回执。MQTT 投递成功不能视为底层寄存器写入成功；本型号如支持实际值回读或错误反馈，须填写已确认的键、主题和报文，否则标记“执行结果反馈待确认”。

### 6.3 上线查询与配置同步

直连设备上线后发布到 `v1/devices/me/attributes/request/7`：

```json
{ "sharedKeys": "【已确认配置键】" }
```

平台在 `v1/devices/me/attributes/response/7` 应答，末级请求序号保持一致：

```json
{ "shared": { "【已确认配置键】": 30 } }
```

网关发布到 `v1/gateway/attributes/request`：

```json
{ "id": 1, "device": "【子设备名称】", "client": false, "keys": ["【已确认配置键】"] }
```

平台在 `v1/gateway/attributes/response` 应答：

```json
{ "id": 1, "device": "【子设备名称】", "values": { "【已确认配置键】": 30 } }
```

单键 `key/value`、设备属性查询及缺失键的处理遵循公共指南第 8.3、9.3 节。查询返回的是平台保存的属性，不代表刚刚读取了设备寄存器。
