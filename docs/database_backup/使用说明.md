# ThingsBoard 生产数据库每日备份

## 已配置的默认值

- 数据库：localhost:5432/thingsboardpe，用户 postgres。
- PostgreSQL 工具目录：C:\Program Files\PostgreSQL\18\bin，若服务器路径不同，修改 Backup-ThingsBoard.ps1 参数默认值。
- 成功归档目录：C:\appdir\database_backup\backups。
- 日志目录：C:\appdir\database_backup\logs。
- 每天服务器本地时间 02:30 一次，保留最近 60 份成功 .dump。
- 脚本使用 CUSTOM 压缩归档，不停止 TB，不执行恢复或修改生产业务数据；备份会增加磁盘和数据库负载。

这些文件由开发电脑生成。若生产服务器是另一台机器，请先复制整个 database_backup 文件夹到生产服务器同一路径。尚未执行生产备份，也未注册计划任务。

## 第一步：配置认证与目录权限

将 pgpass.conf.example 复制为同目录 pgpass.conf，用文本编辑器填写实际 PostgreSQL 密码。格式为：

```text
localhost:5432:thingsboardpe:postgres:实际密码
```

密码若含冒号或反斜杠，按 PostgreSQL 规则写为 \: 或 \\。不要使用 XML 转义。推荐保存为无 BOM 的 UTF-8 文件，避免第一行字段匹配失败。

pgpass.conf 是明文凭据。使用目录“属性 → 安全 → 高级”限制该目录访问，仅授权管理员、SYSTEM 和指定运维账号，不让普通用户读取密码或修改计划任务将执行的脚本。上线前务必完成权限设置。

## 第二步：手动执行一次备份

在生产服务器管理员 PowerShell 执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\appdir\database_backup\Backup-ThingsBoard.ps1'
$LASTEXITCODE
```

返回 0 表示该次脚本成功，返回 1 表示失败。检查 backups 中的 .dump 和 logs 中的日志。脚本先写 .dump.partial；导出成功、文件非空且 pg_restore --list 通过后才改名为 .dump，然后清理超出 60 份的旧归档。

失败保留 .partial 和日志供排查，不会清理已有成功备份；失败文件和日志需运维按磁盘情况另行整理。保留数量按成功文件数量而非日龄计算，因此某天失败不会提前删掉可用旧备份。

## 第三步：注册定时任务

确认手动备份正常且目录权限已限制后，在管理员 PowerShell 执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\appdir\database_backup\Register-BackupTask.ps1'
```

任务使用 SYSTEM 身份，用户退出登录后仍可运行。SYSTEM 必须能读脚本及密码文件，能写归档目录。调度使用服务器时区，请确认服务器时钟和时区正确。任务错过时间后会补跑；同名任务存在时注册脚本拒绝覆盖，运行中不会再启动第二份。

查看调度状态：

```powershell
Get-ScheduledTask -TaskName 'ThingsBoard-Production-Database-Backup'
Get-ScheduledTaskInfo -TaskName 'ThingsBoard-Production-Database-Backup'
```

LastTaskResult 为 0 表示上次执行成功，但尚未运行时需结合 LastRunTime 和实际日志判断，不能仅凭 0 判断已备份。脚本没有配置邮件/短信告警，应定期检查最近成功时间、任务结果及剩余磁盘空间；长期卡住的任务需人工排查。

## 备份范围及恢复验证

备份包含 thingsboardpe 单库的结构和数据，不包含 PostgreSQL 全局账号/表空间、TB 程序、服务器配置及外部文件存储。需要另外保存数据库角色配置与程序配置，定期把归档复制到另一台机器或独立存储。

pg_restore --list 仅检查归档目录可读，SHA256 用于日后校验文件，不能证明全部表数据可恢复。应定期将归档恢复到新建的独立临时库进行验证，绝不能直接恢复到生产库。

参数依据：[PostgreSQL pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html)、[密码文件](https://www.postgresql.org/docs/18/libpq-pgpass.html)。本交付仅做 PowerShell 静态语法检查，未连接数据库，也未运行备份、删除归档或注册任务。
