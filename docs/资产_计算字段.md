# ThingsBoard：资产与计算字段

## 1. 计算字段是什么

计算字段（Calculated Field）用于把设备或资产的原始属性、遥测数据、关联实体数据或历史窗口数据，自动加工为新的业务字段。

例如，设备上报 `voltage = 220` 和 `current = 5` 后，可以计算并保存：

```text
power = voltage * current = 1100 W
```

计算结果可保存为时序数据或属性，并可直接在看板、告警规则、导出与自动化中使用。它不是只在某个看板中临时显示的公式。

> 计算字段属于 ThingsBoard PE / Cloud 功能；创建和管理权限属于租户管理员，客户用户不能配置。

## 2. 与其他方式的区别

| 方式 | 主要用途 | 是否保存结果 |
| --- | --- | --- |
| 看板组件 JS | 只改变当前图表或卡片的展示 | 否 |
| 规则链 | 路由消息、创建告警、发送通知、调用外部系统 | 取决于节点配置 |
| 计算字段 | 生成可被系统各处复用的业务指标 | 是 |
| 设备端计算 | 设备已有算力时，在上报前完成计算 | 是 |

建议：指标型计算使用计算字段；通知、工单、第三方接口等流程使用规则链；只影响显示的换算放在看板组件中。

## 3. 可使用的输入与输出

### 输入

- 当前设备或资产的最新遥测数据；
- 客户端、服务端、共享属性；
- 指定设备、资产、客户、租户或实体所有者的数据；
- Script / Propagation 字段可使用历史时序滑动窗口。

### 输出

- **时序数据**：例如 `totalPower`、`energyToday`、`avgVoltage`，可画历史曲线；
- **属性**：例如 `healthScore`、`siteStatus`，适合保存当前状态或分类结果。

## 4. 六种类型

| 类型 | 适用情况 | 示例 |
| --- | --- | --- |
| Simple | 一条数学表达式 | `power = voltage * current` |
| Script（TBEL） | 条件、循环、滚动窗口、多输出 | 负载率、健康评分、异常识别 |
| Propagation | 将值复制或计算后写到关联实体 | 设备状态同步到配电箱 |
| Geofencing | 进入、离开电子围栏 | 运维车辆进入站点 |
| Related entities aggregation | 对关联实体求和、均值、最大值、计数 | 配电房下的在线设备数、总功率 |
| Time series data aggregation | 按小时、日、周等聚合历史数据 | 每日用电量、日最大功率 |

## 5. 与资产结合后的价值

设备负责上报原始数据；资产负责表示园区、站点、配电房、配电箱等业务对象，并汇总下属设备数据。

```text
园区
└─ 站点 / 楼栋
   └─ 配电房
      └─ 配电箱
         ├─ 电表
         ├─ 电气安全设备
         └─ 智能防雷设备
```

### 5.1 资产总览

可在配电房、站点等资产上维护：

```text
totalPower          当前总功率
energyToday         今日总用电量
onlineDeviceCount   在线设备数
offlineDeviceCount  离线设备数
alarmDeviceCount    告警设备数
```

首页的在线环形图、告警卡片、总功率卡片可直接读取资产字段，而不必由每个组件自行遍历所有设备。

### 5.2 分层能源统计

可以在每一层资产计算自己的能耗：

```text
配电箱：energyToday
配电房：下属配电箱 energyToday 之和
站点：下属配电房 energyToday 之和
园区：下属站点 energyToday 之和
```

可用于逐级钻取、区域能耗排行、日/月能耗对比，以及单位面积或单位产量能耗。

### 5.3 状态与健康评分

将下属设备的状态汇总为资产状态：

```text
NORMAL   关键设备均正常
WARNING  存在预警或部分设备离线
ALARM    存在严重告警
OFFLINE  关键设备全部离线
```

也可以输出：

```text
healthScore       0 ~ 100 的健康分
riskLevel         LOW / MEDIUM / HIGH
maintenanceLevel  NORMAL / INSPECT / URGENT
```

评分可综合告警数量、离线数量、接地电阻、浪涌次数、温度电流异常和距离上次巡检的时间。

### 5.4 告警归并

当一个配电箱下多台设备同时异常时，可在资产上生成：

```text
activeAlarmCount = 10
alarmSummary = 配电箱 A：10 台设备存在异常
```

再由资产产生一条“综合异常”告警，避免给运维人员或客户推送大量重复设备告警。

### 5.5 客户数据隔离与看板复用

将资产及其下属设备分配给客户后，相同的看板模板可供不同客户使用，但每位客户只看到自己范围内资产的在线率、告警、能耗和防雷状态。

这适合“客户菜单副本 + 业务看板”的交付模式。

### 5.6 自动标签和筛选

可生成便于检索的资产属性：

```text
region = 华东
siteType = 工业园区
voltageLevel = 10kV
hasLightningProtection = true
energyLevel = HIGH
```

用于筛选“有防雷设备且本月高能耗的站点”等运维对象。

## 6. 推荐的第一批字段

建议优先在“配电房 / 站点”资产中落地：

```text
onlineDeviceCount
alarmDeviceCount
totalPower
energyToday
lightningProtectionStatus
healthScore
```

其中：

- 通用电参量可放在 Device Profile；
- 站点、配电房、配电箱的汇总字段可放在 Asset Profile；
- 个别特殊对象的逻辑放在单个设备或资产上。

Profile 级和实体级的匹配计算字段会同时运行，不互相覆盖。

## 7. 注意事项

- 建议统一键名，例如 `totalPower`、`energyToday`，避免同一概念存在多种命名；
- 不要把通知、工单、外部 API 调用等复杂流程塞入计算字段，应交给规则链；
- 避免字段之间形成循环依赖；
- 新建或修改计算字段后，历史数据不会自动完整回填；如需补算，应使用 Reprocessing；
- 默认配额通常包含每实体 / Profile 的字段数、每字段参数数、历史窗口数据点数等限制，可在 Tenant Profile 调整。
