# 智能防雷与告警页面实时订阅设计

## 目标

为智能防雷和告警页面补齐缺失的 WebSocket 实时通知，使设备状态、活动告警、告警统计和告警分析在页面停留期间能够自动刷新；历史曲线仍使用已有 HTTP 查询。

## 范围

- 智能防雷看板：设备状态、地图状态、地网/SPD/雷电实时汇总、告警列表和告警统计。
- 数据监测：继续复用现有实时订阅，并统一到共享订阅服务。
- 设备详情：当前设备实时指标和设备告警。
- 数据查询：设备状态、告警状态和资产树标记。
- 告警列表、告警派发、告警处理：新增告警、确认、清除和派发状态。
- 告警分析：周期统计、站点排名、类型/严重程度排名、趋势和重点设备。

不改历史遥测曲线的 HTTP 查询，不新增后端接口，不运行 Maven。

## 方案

新增全局 `SmartLightningRealtimeService`，复用现有 `TelemetryWebsocketService`、`EntityDataCmd`、`AlarmCountCmd` 和 `AlarmDataCmd`。服务对外提供设备变更与告警变更通知，并通过引用计数控制订阅生命周期：首个页面进入时建立订阅，最后一个页面销毁时取消订阅。

WebSocket 只作为轻量失效通知。页面收到通知后使用现有 HTTP 聚合接口重新读取，继续沿用既有权限过滤、资产树过滤、告警去重和 DTO 映射，避免在多个页面复制业务逻辑。所有页面在刷新通知上使用 `auditTime(600)` 合并高频遥测事件。

## 订阅内容

- 设备实体：服务器属性 `active`。
- 规范实时遥测：`spdStatus`、`groundStatus`、`temperatureA`、`temperatureB`、`temperatureC`、`temperatureD`、`lifePercent`、`leakageA`、`leakageB`、`leakageC`、`groundResistance`、`surgeCount`、`surgePeak`、`surgePolarity`、`deviceStatus`、`arcFaultCount`。
- 活动告警数量：使用 `AlarmCountCmd` 监听新增、激活或清除导致的数量变化。
- 活动告警字段：使用 `AlarmDataCmd` 监听确认、派发、备注等数量不变的告警字段变化。

## 刷新边界

- 设备变更：刷新设备状态、地图状态、实时指标和设备卡片；不重新查询历史曲线。
- 告警变更：刷新告警列表、资产树标记、告警统计、站点排名、严重程度分布和重点设备。
- 周期切换：仍由页面主动调用原有 HTTP 周期接口，不依赖 WebSocket。

## 验收标准

1. 两个目标目录中不再为每个页面重复创建独立的全量 WebSocket 连接。
2. 页面首次进入仍能通过已有 HTTP 请求正常显示初始数据。
3. 设备状态或实时遥测变化后，相关页面自动刷新且不刷新浏览器。
4. 新增、确认或清除告警后，告警列表、资产树标记和分析统计自动刷新。
5. 页面销毁后订阅被释放，不残留 WebSocket 监听。
6. 不改变已有接口返回结构、排序规则、筛选规则和历史曲线行为。
