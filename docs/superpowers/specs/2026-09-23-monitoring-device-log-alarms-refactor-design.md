# 监控、设备日志与告警服务职责整理设计

## 1. 目标

基于当前工作树，对 `monitoring`、`deviceLog`、`alarms` 三个自定义服务目录进行有依据的职责整理：只拆分确有独立职责、可通过明确输入输出协作的实现；保持已有接口和业务结果；修正静态检查已确认的空值及计数边界问题。避免仅为降低行数而制造一层层代理类。

本设计已明确排除故障电弧相关调整。故障电弧遥测键尚未确认，因此不改其字段、换算/聚合逻辑、DTO/VO、遥测映射或相关服务代码。

## 2. 当前职责判断

- `SmartLightningDashboardServiceImpl` 在一个大文件内实现地网、SPD、雷电流三个独立板块。它们对外是同一页面服务，但各自有单独的数据、查询和汇总流程；公共设备过滤、分批遥测读取、告警聚合可保留为共享支持逻辑。
- `DeviceLogServiceImpl` 同时负责用户设备权限、数据查询/分页/合并和审计 JSON 展示转换。权限、数据访问与分页属于服务编排；审计字段格式化是可独立验证的纯转换职责。
- `DeviceAlarmAnalysisServiceImpl` 的摘要、趋势、排行、末级资产计数和重点告警围绕同一分析场景，当前已有统计查询服务承接数据库聚合。它仍然是一个内聚的应用服务，不因行数较多再拆子服务。
- 其余监控设备查询、树构建、计算器、VO 转换、告警统计查询和仓储适配均保持现有边界；不按单个方法或 DTO 继续拆类。

## 3. 目标结构

### 3.1 看板板块处理器

保持 `SmartLightningDashboardService` 对外接口、`@Service` 实现和三个公开方法不变。`SmartLightningDashboardServiceImpl` 仅负责依赖组装和请求转发，将当前三个私有嵌套处理器分别提取为同包 package-private 类：

- `GroundSummaryHandler`：地网摘要及接地阻值范围。
- `SpdSummaryHandler`：SPD 实时状态、周期指标和汇总。它作为一个完整板块保留，不再按指标拆成多个处理器。
- `LightningCurrentSummaryHandler`：雷电流摘要、峰值和浪涌计数。
- `SmartLightningDashboardSupport`：只承载三个处理器共同使用的分批遥测读取、功能分类设备筛选和告警聚合逻辑及其结果类型。

处理器保持普通 package-private 类，由现有服务构造函数显式创建，不额外注册 Spring Bean。这样不改变服务发现或注入关系，同时使每个板块可以独立阅读。共享实现只保留一份，不复制到各处理器。

### 3.2 设备日志审计转换

新增同包 `DeviceLogAuditTimelineConverter`，负责把 `AuditLog` 及其 action data 转为时间线 DTO：动作标题、操作者、属性变化、关系端点、JSON 值和详情文本等展示转换都放在此处。

`DeviceLogServiceImpl` 继续负责设备可见性和 READ 权限校验、平台查询、批量实体名称读取、游标、来源合并、时间过滤、排序和分页。转换器只接收审计记录及服务已解析的 `EntityInfo` 映射，不调用数据库或绕过服务权限边界。

保留 `DeviceLogServiceImpl.toActivityTimelineItems` 的 package-static 委托入口，以兼容当前已有的同包测试/调用约定；本次不改变 active 时序去重和排序语义。

### 3.3 告警分析保持内聚

不拆分 `DeviceAlarmAnalysisServiceImpl`。只处理已确认的冗余和计数边界：末级资产的计数在 `long` 范围内累加；摘要多个类型的计数也先以 `long` 累加，仅在写入既有 `int` DTO 字段时调用现有饱和转换；移除对只读树索引映射的多余复制；`AlarmPeriodWindow` 的 Lombok getter 与手写等价 getter 保留一种实现。

不改公开 DTO 字段类型、API、数据库表或统计口径。

## 4. 需要保持或修正的行为

1. **服务契约**：不改 Controller 路由、公开 Service 方法签名、DTO/VO 结构、权限入口、周期定义、排序口径或分页格式。
2. **设备上下文空属性**：批量属性查询没有返回某设备的属性时，该设备应仍可安全构造上下文。将缺失属性表按空映射处理，避免 `attributes.get(...)` 引发空指针；产品分类过滤规则保持现有语义。
3. **坐标解析**：复用现有 `MonitoringValueParser` 的有限数值解析能力，同时保留纬度/经度范围校验；无值、非数值、无穷值或越界坐标仍映射为 `null`。
4. **告警计数**：在聚合期间不提前窄化 `long` 计数；输出仍遵守现有 DTO 字段范围和饱和规则，避免多设备或多类型计数在中间步骤溢出。
5. **客户设备日志告警范围**：客户查询当前未可靠应用 `affectedEntityId`，可能把同客户其他设备的告警并入所选设备时间线。修正后，客户和租户用户的告警事件都必须属于所选设备；客户结果还必须限定当前客户。查询和翻页使用现有平台服务 API，不修改原生 DAO/Repository。若需要跨源分页扫描，应持续推进源分页直到取得当前页所需的目标设备事件或源数据耗尽，并据此计算 `hasNext`，不能只过滤单页后返回不准确游标。
6. **展示转换优化**：删除审计/告警事件在同一查询路径中重复执行且结果已由统一时间过滤覆盖的时间范围判断；最终时间过滤仍保留并继续拒绝非正时间戳。
7. **告警分析服务**：保持其现有聚合和排序结果，只修复上述计数精度与确定的重复实现，不新增职责相同的包装服务。

关系端点的名称解析继续由 `DeviceLogServiceImpl` 批量完成，转换器只格式化已有解析结果；本次不调整实体名称可见性策略，以免在缺少明确平台权限语义时改变页面可见数据。

## 5. 明确不在本次范围内

- 故障电弧相关服务逻辑、DTO/VO、键名、遥测映射、计数含义和字段注释；在用户确认标准遥测键以前全部保持原样。
- `SmartLightningMonitoringServiceImpl` 的实时监控各板块拆分，以及看板 SPD handler 的进一步子拆分。
- 监控 VO 转换器按端点拆类，或告警分析服务按方法拆为多个 Spring Bean。
- 关系实体名称的权限策略、active 遥测是否代表状态切换的产品语义、时间游标精度等其他行为变更；若后续确认需要修复，另行设计。
- 修改 ThingsBoard 原生 Controller、DAO、Repository、表结构或平台接口。
- 扩展到目标目录外的前端或其他业务模块。

## 6. 验收边界

- 三个看板接口的服务/API 和各自现有聚合结果保持不变；板块实现可以按文件独立定位，共享查询行为没有重复实现。
- 设备日志编排保留在服务中，审计展示格式集中于纯转换器；客户设备时间线不会混入同客户其他设备的告警，翻页结果不因该过滤而漏页或生成错误的空游标。
- 缺失设备属性不会导致上下文构造空指针；计数聚合在 DTO 输出边界前保持 `long` 精度。
- 告警分析仍保持单一内聚服务；故障电弧文件和语义不在变更范围。
- 项目 `AGENTS.md` 禁止未经当前明确授权运行 Maven 及其生命周期/测试命令。本轮按源码静态检查和差异审查验证；不运行 Maven、测试或构建。

## 7. 实施约束

当前仓库有大量用户未提交修改。实施必须基于当前工作树逐文件核对，仅修改本设计列出的自定义实现及必要的新处理器/转换器文件；不能重置、覆盖或顺手提交其他已有修改。新写业务注释使用中文。任何发现与本设计冲突的平台 API 或权限约束，都先暂停对应改动并向用户说明，不修改原生 DAO/Repository 来绕过边界。
