# 设备日志页面设计

## 1. 目标

新增一个面向客户用户的“设备日志”页面。页面入口先显示设备列表，列表只展示设备名称、设备配置类型和操作按钮；点击“查看日志”后，从右侧打开设备日志侧边栏。

侧边栏包含三个相互独立的页签：

1. 服务器属性
2. 最新遥测
3. 事件时间轴

本功能只修改项目自定义模块，不修改 ThingsBoard 原生页面、原生 Controller、原生 Service 或原生数据结构。

## 2. 页面结构

```text
设备日志页面
├── 筛选区
│   ├── 根资产
│   ├── 资产/设备
│   ├── 设备配置类型
│   ├── 设备名称搜索
│   └── 重置
├── 设备列表
│   ├── 设备名称
│   ├── 设备配置类型
│   └── 查看日志
└── 设备日志侧边栏
    ├── 设备摘要
    ├── 服务器属性
    ├── 最新遥测
    └── 事件时间轴
```

主列表不显示告警类型、告警级别、时间、属性值或遥测值，避免页面入口承担日志详情职责。

## 3. 侧边栏页签

### 3.1 服务器属性

显示当前设备的服务器属性快照：

- 属性名称
- 属性值
- 更新时间

优先显示产品名称、产品分类、功能分类、设备协议、设备地址、所属位置等项目已有属性。不存在的属性不显示空占位行。

### 3.2 最新遥测

显示当前设备最新一条遥测值：

- 测点名称
- 当前值
- 单位
- 更新时间

该页签是当前状态快照，不是历史遥测曲线。历史曲线继续复用数据查询和设备详情页面。

### 3.3 事件时间轴

显示平台产生的、对用户有意义的设备事件：

- 设备上线、离线和重新连接
- 告警触发、确认、派发和清除
- RPC 或设备操作的执行结果
- 关键服务器属性变更
- 设备创建、删除或资产关联变化

普通遥测每次上报不直接生成时间轴记录，否则会产生大量低价值数据。普通遥测仍通过“最新遥测”和历史数据查询查看。

每条事件包含：

- 发生时间
- 事件分类
- 事件级别
- 事件标题
- 事件说明
- 事件来源
- 执行结果

## 4. 数据来源与后端边界

新增自定义设备日志服务只负责聚合现有平台数据，不复制 ThingsBoard 原生表结构：

- 设备列表：复用当前用户可见设备查询和权限过滤。
- 服务器属性：复用属性服务读取 `SERVER_SCOPE`。
- 最新遥测：复用时序服务最新值查询。
- 告警事件：复用告警服务和现有告警状态字段。
- 操作、审计和关键属性变更：优先复用现有 AuditLog 能力。
- 上线/离线：复用平台已有设备活动状态和事件数据；没有历史事件来源时，不伪造历史记录。

建议由一个自定义聚合接口返回设备详情侧边栏所需的结构，避免前端在打开侧边栏后并发调用过多接口：

```text
GET /api/device-log/devices
GET /api/device-log/devices/{deviceId}/server-attributes
GET /api/device-log/devices/{deviceId}/latest-telemetry
GET /api/device-log/devices/{deviceId}/events
```

其中事件接口必须分页，并按照发生时间倒序返回。若平台数据源只能按 `createdTime` 查询，接口必须在注释中明确时间口径，不能把创建时间伪装成设备事件发生时间。

## 5. 实时更新

设备日志侧边栏首次打开时分页读取历史事件；打开期间通过 WebSocket 接收当前设备的新事件，并将增量事件插入时间轴顶部。

实时订阅范围只包含当前选中的设备，关闭侧边栏或切换设备时取消旧订阅，防止多个设备订阅叠加。

如果某类平台事件暂时没有可靠的 WebSocket 来源，先保持历史查询，不使用高频轮询伪装实时能力。

## 6. 权限与数据隔离

- 所有设备查询必须基于当前登录用户可见范围。
- 客户用户只能看到自己有权限的设备、属性、遥测和事件。
- 事件接口必须再次校验 `deviceId` 是否属于当前用户可见范围，不能信任前端传入的设备 ID。
- 服务器属性和审计详情中可能包含敏感信息时，只返回页面必要字段。

## 7. 前端组织

建议新增自定义目录：

```text
ui-ngx/src/app/modules/home/pages/device-log/
├── device-log.module.ts
├── device-log-routing.module.ts
├── device-log-list.component.ts/html/scss
├── device-log-api.service.ts
├── device-log.models.ts
├── device-log-server-attributes.component.ts/html/scss
├── device-log-latest-telemetry.component.ts/html/scss
└── device-log-event-timeline.component.ts/html/scss
```

组件职责：

- `device-log-list`：筛选、分页、设备列表和侧边栏打开状态。
- `device-log-server-attributes`：服务器属性展示。
- `device-log-latest-telemetry`：最新遥测展示。
- `device-log-event-timeline`：事件筛选、时间轴、分页和增量更新。
- `device-log-api.service`：集中管理 HTTP 请求和 WebSocket 订阅。
- `device-log.models.ts`：定义请求、响应和事件类型，不在模板中重复写接口结构。

## 8. 后端组织

建议在自定义 Service 下建立独立模块，不放入 ThingsBoard 原生业务包：

```text
application/src/main/java/org/thingsboard/server/service/deviceLog/
├── service/
│   ├── DeviceLogService.java
│   └── impl/DeviceLogServiceImpl.java
├── dto/
├── bo/
├── vo/
├── converter/
└── util/
```

Controller 只负责路由、参数、权限入口和 DTO→VO 转换；Service 负责设备可见性、数据聚合和事件排序；Repository/平台服务负责读取数据；Converter 只负责对象转换。

## 9. 分阶段实施

### 第一阶段

- 新增设备列表页面。
- 接入服务器属性和最新遥测页签。
- 接入已有告警事件时间轴。
- 实现当前用户权限过滤和分页。

### 第二阶段

- 接入上线/离线事件。
- 接入 RPC 操作结果。
- 接入关键属性变更。
- 增加 WebSocket 增量更新。

### 第三阶段

- 增加时间轴分类、级别和关键字筛选。
- 增加事件导出。
- 根据实际数据量增加归档和保留策略。

## 10. 不在本次范围内

- 不记录每一条普通遥测上报为日志。
- 不新增 Java 后端运行日志页面。
- 不复制 ThingsBoard 原生告警表、审计表或时序表。
- 不修改原生设备页面和原生审计日志页面。

## 11. 原生页面借鉴边界

本功能是完全新建的自定义页面和自定义模块。原生设备页面只作为交互和信息组织参考，不直接复用原生页面组件、模板、样式或页面路由。

允许复用的是平台底层能力和数据语义，而不是原生页面实现：

- 使用平台已有的实体权限校验能力，但在自定义设备日志接口中重新组织调用。
- 使用平台已有的服务器属性、最新遥测、告警和审计数据服务作为数据来源。
- 借鉴原生页面的页签命名、属性表布局、最新值展示方式和详情侧栏交互。
- 自定义实现 `device-log` 的 Angular 组件、模板、样式、数据模型和 API Service。
- 自定义实现设备日志后端 Controller、Service、DTO、BO、VO、Converter 和事件聚合逻辑。
- 原生 `tb-audit-log-table`、原生设备详情组件及其配置只能阅读和参考，不在本功能中导入、改写或扩展。
- 自定义接口必须再次校验设备可见范围，不能因为调用了平台底层服务就跳过权限过滤。
