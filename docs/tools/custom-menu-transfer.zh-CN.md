# 通过网页 Console 迁移 test 自定义菜单

两端需使用所属租户的管理员账号登录。脚本只使用当前登录页面的同源接口，不需要填写密码或复制令牌。先等待测试环境能够正常登录。

## 1. 在本地导出

1. 打开本地 ThingsBoard，进入“白标 → 自定义菜单”，确认有名称精确为 `test` 的菜单。
2. 打开浏览器开发者工具的 Console。
3. 将同目录 `custom-menu-export.console.js` 的全部内容复制进去执行。
4. 保存下载的 `thingsboard-custom-menu-test.json`，将文件带到测试服务器。

脚本遍历全部菜单分页，只匹配 `test`，不会匹配 `test - 副本`。有多条同名菜单时停止。不会修改本地菜单。

## 2. 在测试环境导入

1. 在测试服务器浏览器打开 `http://127.0.0.1:18080` 并以目标租户管理员登录。
2. 在 Console 执行 `custom-menu-import.console.js` 全部内容。
3. 文件选择框中选择刚导出的 JSON。
4. 核对确认框中的目标地址为测试环境，再确认创建。
5. 看到配置回读校验通过后，刷新“白标 → 自定义菜单”列表。
6. 新菜单为“未分配”。使用齿轮按钮选择目标测试用户并保存，重新登录或刷新验证侧栏。

脚本拒绝对导出来源的相同 origin 导入，且拒绝覆盖目标同名菜单。origin 指协议、主机和端口；如果两台电脑都使用 localhost 同一端口访问，需改用其中一端的真实主机地址访问后重新导出，不能仅凭该检查判断环境。

创建和写入配置是两个 API 操作，不是原子事务。中途失败可能留下未分配菜单；脚本会显示 ID，需到页面核对后再处理，不能盲目重复执行。

## 迁移范围

- 保留菜单名称、层级、顺序、图标、链接和完整配置。
- 不复制原菜单 ID、租户 ID、用户分配 ID、密码和登录令牌；目标由当前登录租户接收。
- 不自动迁移仪表板、图片、客户、角色等关联资源，也不自动重写配置中的实体 ID、绝对 URL 或资源路径。导入前应检查 JSON 中这些引用是否适用于测试环境。
- 菜单并不授予业务权限；被分配用户仍需有目标页面和资源的访问权限。
- JSON 可能含内部地址或资源引用，应妥善保存。不要在陌生网站执行脚本。

## 接口依据与验证范围

接口来自项目 `CustomMenuController` 和前端 `CustomMenuService`：分页 GET `/api/customMenu/infos`、配置 GET/PUT `/api/customMenu/{id}/config`、创建 POST `/api/customMenu?force=false`。菜单创建采用 `TENANT` / `NO_ASSIGN`。

此交付仅静态核对源码契约，未实际登录、导出或写入任何环境。运行时脚本会检查 HTTP 状态，并在导入后回读比对配置。
