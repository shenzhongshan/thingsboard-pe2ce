# 智能防雷看板实现评估

## 1. 结论

参考图中的页面约 **80% 可直接用 ThingsBoard 原生组件实现**；地图气泡不纳入本次范围。所有图表的“日 / 周 / 月”筛选器必须使用自定义组件，不能显示或使用 ThingsBoard 原生时间窗口选择器；带业务字段的告警记录表可按实际需要定制。

推荐路线不是重写前端页面，而是：

1. 保留现有 ThingsBoard Dashboard；
2. 统一实体别名、遥测键和全局时间窗口；
3. 以原生图表、地图、告警表完成主体；
4. 制作“日 / 周 / 月”专用时间筛选 Widget，替代原生时间窗口入口；仅在需要时再制作业务告警表；
5. 将完成后的 Dashboard / Widget Bundle 导出 JSON 备份并纳入项目版本管理。

## 2. 已有旧页面核对结果

核对对象：现有 Dashboard **智能防雷看板**（`8a4c60a0-a05d-11f1-b221-294746b2c334`）。

当前已存在：

| 部分 | 当前实现 | 结论 |
| --- | --- | --- |
| 设备汇总 | 自定义 `Attributes card`，含防雷设备总数、在线、离线、告警数量 | 可改造成参考图左上“设备信息” |
| 在线/离线占比 | 原生 `system.horizontal_doughnut` | 可直接复用 |
| 地图 | 原生 `system.map`，已配置天地图图层、经纬度属性与点位 | 可直接复用并升级样式 |
| 告警 | 原生 `Alarms table`，目前含 `SPD_LOW_LIFE`（寿命关注）筛选 | 可复用，但需扩大筛选和列定义 |
| 设备列表 | 原生 `Entities table`，已有 `spdStatus`、`lifePercent`、`active` 数据源 | 可作为设备明细或数据查询入口 |
| 设备详情子状态 | 设备总数、在线数、环形图等原生组件 | 可保留作点地图标记后的设备详情 |

旧页面中已有 `alertInfoDay`、`alertInfoWeek`、`alertInfoMonth` 三个 Dashboard State，但三个状态目前没有 Widget。因此，日/周/月切换的结构想法已经存在，图表本身尚未配置。

## 4. 日 / 周 / 月筛选：必须自定义

### 实现原则

- 不显示 Dashboard 工具栏中的原生 Time Window；
- 不显示各原生图表右上角的原生时间窗口按钮；
- 只显示自定义的 **日 / 周 / 月** 三段按钮；
- 原生趋势图、柱图、告警表仍启用 **Use dashboard time window**，只是不让用户直接操作原生入口；
- 自定义按钮调用 Dashboard Time Window API 更新统一的时间范围。

这样用户只能选择日、周、月，不会出现“最近 15 分钟、最近 6 小时、自定义日期”等不符合页面设计的选项。

### 三个固定窗口

可定义三组含义：

| 按钮 | 建议窗口 | 推荐聚合 |
| --- | --- | --- |
| 日 | 当天 00:00 至当前时间，或最近 24 小时 | 5 分钟 / 1 小时，AVG、SUM 或 COUNT |
| 周 | 本周一 00:00 至当前时间，或最近 7 天 | 1 小时 / 1 天 |
| 月 | 本月 1 日 00:00 至当前时间，或最近 30 天 | 1 天 |

优点：所有图表、告警记录同时切换，数据口径一致；原生时序 Widget 与 Alarm Widget 都支持 Dashboard Time Window。

### 自定义组件：`防雷周期选择器`

做一个很小的 Static / Custom Widget，显示“日 / 周 / 月”三个按钮。点击后调用 Dashboard Time Window API 更新全局范围；其他图表仍是原生图表。

建议将这个选择器放在 Dashboard 顶部，作为所有图表的唯一真实筛选器。若视觉上必须像参考图一样每一张图右上角都有“日/周/月”，可额外放置只显示当前选中状态的轻量同步组件；但所有按钮都更新同一全局时间范围，避免每张图的数据口径不同。

不建议为日、周、月分别复制三张完整看板或让每张原生图单独配置时间窗口；这样后期改一条遥测键就要修改多处，容易数据不一致。

> 若业务明确要求“每张图可以独立选择日、周、月，且互不影响”，则该图必须改为自定义图表 Widget；原生图表无法由外部按钮分别修改它自己的私有时间窗口。本方案默认所有图表统一切换。

## 5. 建议的数据模型与遥测键

键名必须以设备实际已上报的遥测为准；以下是推荐规范，不应在未核实协议前强行改名。

| 业务区域 | 推荐时序键示例 | 用途 |
| --- | --- | --- |
| 设备状态 | `active`、`spdStatus`、`lifePercent` | 在线、SPD 状态、寿命 |
| SPD 监测 | `leakageCurrent`、`residualCurrent`、`lineVoltage`、`groundCurrent` | 四线趋势图 |
| 地网监测 | `groundResistance`、`soilResistivity`、`groundVoltage` | 地网趋势图，具体以实际传感器为准 |
| 雷电监测 | `lightningCurrentPeak`、`lightningStrikeCount`、`dischargeEnergy`、`chargeTransfer` | 横向条形图与统计 |
| 告警统计 | `lightningAlarmCount`、`tripAlarmCount`、`spdFailureCount` | 报警柱图；也可由规则链把告警事件写为计数时序 |
| 工单统计 | `workOrderPendingCount`、`workOrderProcessingCount`、`workOrderDoneCount` | 工单柱图；来自工单模块或外部系统同步 |

对于多个防雷设备的汇总，建议在“站点 / 配电房”资产上使用 Calculated Fields 或规则链生成：

```text
onlineDeviceCount
offlineDeviceCount
alarmDeviceCount
lightningProtectionStatus
healthScore
```

看板的汇总卡直接读取资产字段，避免每个 Widget 各自统计下属设备。

## 6. 地图实现方式

- 天地图、OpenStreetMap 等底图；
- 使用 `latitude`、`longitude` 属性定位；
- 根据状态改变标记图标、颜色；
- 点击或悬浮 Tooltip；
- 点击标记进入设备详情 Dashboard State；
- 聚合大量点位。

本次不实现参考图中的彩色信息气泡。地图保留现有原生点位即可；需要详情时点击标记进入已有设备详情 Dashboard State，或使用简洁的原生 Tooltip。

## 7. 告警与工单的处理建议

### 告警记录

优先复用原生 Alarms table，并将筛选由当前单一 `SPD_LOW_LIFE` 扩展为智能防雷相关类型，例如：

```text
SPD_LOW_LIFE
SPD_FAILURE
GROUND_RESISTANCE_HIGH
LIGHTNING_EVENT
DEVICE_OFFLINE
```

原生表适合展示告警来源、类型、严重级别、状态、创建时间，并支持确认、分配、清除（是否给客户开放这些操作需另行决定）。

参考图中的“位置名称、次级位置名称、设备型号、设备编码、设备位置、异常发生事件”属于业务字段：

1. 简化方案：写入 Alarm Details，或用来源名称替代部分字段；
2. 高还原方案：做自定义告警表，读取 Alarm + 设备属性 + 资产关系，并按需要展示字段。

### 运维工单

若工单已存在于外部运维系统，建议用规则链或后端接口将“未处理、未派发、已处理”的每日统计同步为站点资产的遥测，再用原生 Bar chart 展示。

若要在 ThingsBoard 内完整创建、指派、流转、关闭工单，则这不只是一个看板 Widget，需要独立设计工单数据模型、权限和后端接口；不建议先在 Dashboard 中硬做。

## 8. 外部组件与自定义组件

### 可导入的内容

ThingsBoard 可导入：

- 单个 Widget 的 JSON；
- 整个 Widget Bundle 的 JSON；
- 整个 Dashboard 的 JSON。

导入后仍需重新绑定目标 Dashboard 的 Entity Alias / 数据源。导入 JSON 不会携带真实设备数据。

### 不建议的方式

不能把任意 Vue、React、NPM 组件直接拖入 Dashboard 使用。外部组件若要进入 ThingsBoard，需要改造成 Widget Bundle / Custom Widget 的 HTML、CSS、JavaScript 配置，或修改 `ui-ngx` 源码并重新构建。

### 推荐的自定义组件清单

| 组件 | 优先级 | 原因 |
| --- | --- | --- |
| 全局日/周/月时间按钮条 | 必须 | 禁用原生时间筛选后，作为全部图表唯一的时间入口 |
| 业务告警记录表 | 中 | 仅在必须展示资产层级、型号、编码等字段时制作 |
| 顶部状态计数条 | 低 | 原生卡片已可实现，定制只为贴近视觉 |
| 设备信息总览卡 | 低 | 现有自定义卡与原生环图已能完成 |

## 9. 建议实施顺序

1. **核对实际遥测键与告警类型**：确认现有设备到底上报哪些 SPD、地网、雷电键；
2. **整理资产关系**：站点 / 配电房 / 配电箱 / 防雷设备的 Relation；
3. **建立资产汇总字段**：在线数、告警数、健康状态、总雷击次数等；
4. **调整现有 Dashboard 主布局**：保留设备卡、地图、告警表、实体表；
5. **增加四张原生图表**：地网趋势、SPD 趋势、雷电条图、报警柱图；
6. **接入自定义日/周/月按钮条**：隐藏原生时间入口，所有图表统一使用 Dashboard Time Window；
7. **视验收效果补充业务告警表**；
8. **导出 JSON 并保存到项目**：Dashboard 与 Widget Bundle 分开版本管理。

## 10. 验收标准

- 页面中不存在原生时间窗口选择器，用户只能选择日、周、月；
- 日、周、月切换后，四张图表和告警记录使用同一时间范围；
- 设备点位能根据在线、预警、告警状态变色；
- 地图点位能打开设备详情；
- 无数据时图表显示明确空状态，不显示误导性的 0；
- 客户角色只能查看其分配的设备、资产与告警；
- 所有业务图表使用已确认的实际遥测键，不使用截图中的占位字段。
