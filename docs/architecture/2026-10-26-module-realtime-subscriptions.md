# 按模块拆分实时订阅（2026-10-26）

## 采用方案

使用一个平台公共 TelemetryWebsocketService 物理连接，各业务模块独立维护查询命令、事件、缓存和引用计数。不是给各模块建立新的 WebSocket 连接，也不是先查询全量设备再在前端过滤。

| 调用方 | 注入实例 | productCategory 过滤 | 时序测点 |
| --- | --- | --- | --- |
| 防雷看板、监测、查询、详情 | SmartLightningRealtimeService | lightning | 防雷型号定义中的规范键及 WF |
| 电气安全看板、监测、查询、详情 | ElectricalSafetyRealtimeService | electrical_safety | 电气安全型号定义中的规范键 |
| 能源监管看板与能源实时适配层 | EnergyRegulationRealtimeService | energy_regulation | E1A2 测点定义中的规范键 |
| 首页、通用告警列表、通用告警分析 | ProductRealtimeService | 不按产品分类过滤 | active、lastActivityTime、GPS 坐标 |

各实例还读取产品分类、功能分类、产品名称、服务器坐标和设备名称/类型等原有轻量上下文字段。GPS 遥测、告警状态、设备增减与资产关系变化的通知保持原有能力。

## 公共与业务边界

- 公共实现：`ui-ngx/src/app/shared/realtime/product-realtime.service.ts`，负责构造平台原生查询、合并最新值、分发事件与释放订阅。
- 各模块实现：保留在各自 shared 目录，维护本模块分类值与测点集合。
- 防雷清单直接由已有型号测点数组导出，不再混入电气安全或能源监管的键。
- 首页/通用告警页直接依赖公共实现，不依赖防雷分类订阅。
- 不改动 ThingsBoard 原生 WebSocket 服务、后端接口、权限过滤或设备分类数据。

## 查询与生命周期

- EntityDataCmd、AlarmCountCmd、AlarmDataCmd、设备 EntityCountCmd 都采用相同的 SERVER_ATTRIBUTE.productCategory 原生等值 keyFilter。
- 资产计数仍为全局轻量通知，因为资产可能跨产品模块，不能按设备产品属性过滤资产。
- 同模块多个页面共用 root 单例；首个消费者进入时建立该模块命令，最后一个消费者退出时取消本模块命令和缓存。
- 模块间引用计数与完整首帧状态互不干扰；释放一个模块不清理另一个模块。
- 继续沿用现有单查询 pageSize=10000 上限。本次不实施分页/用途分层方案；若平台返回 hasNext=true，不把这份截断数据标为完整快照，统计保留后端口径。

## 验证范围

核对全部现有注入调用方与原生查询类型；执行 TypeScript、Angular 模板静态检查和 git diff --check。未运行 Maven、测试或浏览器性能实测，因此不宣称具体首屏耗时或加速比例。

## 数据库字段超限修正

后端日志确认电气安全全量遥测订阅生成查询时出现“字段个数 (1857) 超出限制 (1664)”。公共实时服务改为基础上下文独立一批，业务遥测每批最多 32 个键，各批继续使用本模块产品分类过滤和同一平台 WebSocket 连接。基础命令单独读取设备名称和类型，避免每批首帧都触发上下文重新加载。

各批按设备与遥测键合并到原有缓存；所有批次返回未截断且设备集合相同的快照后，才标记本地快照完整。失败批次不计入完成状态。现有告警、设备计数、资产计数和引用计数规则保持不变，最后一个消费者退出时统一取消全部批次。

修正后执行公共实时服务 TypeScript 静态检查和内存模拟订阅验证：覆盖 309 个业务键无遗漏、每批上限、分类过滤、首帧完整性、截断、设备集合不一致、错误响应、旧值保护、引用计数及重新进入清理，均通过；git diff --check 通过。未运行 Maven，尚未在浏览器和真实数据库验证修正后的响应及首屏耗时。
